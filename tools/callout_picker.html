Load a screenshot, click each control to drop a numbered pin, name it, then copy the coordinates straight into place_callouts.py — no more eyeballing pixel positions from a flat image.

Each section below expands on its own — open the ones you need and leave them open while you work through the steps.

First things first

Step 3 needs an AI agent that can actually read your project's source code — not a plain chatbot in a browser tab that's only ever seen the screenshot. Claude Code, Codex, GitHub Copilot Chat, and Cursor are all examples of the right kind of tool.

As a product manager, you may have to work with the software engineers who do have access to the code to get the JSON file you need in the appropriate raw JSON format.

ONDA Docs doesn't set that part up for you — it assumes it's already installed, or you are working with the developers who can help you.

Get yourself or your technicians lined up before you get to step 3. If you don't have one of these running yet, that's the actual first thing to sort out, before anything on this page will make sense.

The architecture of a help file

A help file describing the location and function of controls on a page guides a user to successful completion of a given task. Creating those control locations is the first step, and it's made of four elements:

  1. An image of the page or screen — provided by the product manager.
  2. A numbered pin next to each control — identified by the AI agent.
  3. A label for the control — created by the AI agent.
  4. Text describing what the control does — created by the AI agent.

Elements 2, 3, and 4 are put into one coded object for each pin — a little bundle of { pin number, label, description }. Every one of those objects goes into an array that holds every pin's location, label, and description for the whole screen. That array becomes part of one HTML file.

The image and that HTML file together are what control everything the help screen actually shows: where the pins sit, what they're called, and what they do.

The help file lives separately from the app itself, so it can be changed — in part or in whole — as the app evolves over time, without ever touching the app's own code.

Documenting a screen for the first time
  1. Element 1, the image: take a screenshot of the screen you want to document. Save it anywhere as a PNG or JPG — you'll pick it in step 2.
  2. Load it here with "Choose a file," or drag it straight onto the box below.
  3. Elements 2, 3, and 4 — this is the step that does the real work. Open a chat with your AI agent (Claude Code, Codex, etc. — something with access to the actual source code) and ask it something close to this, filling in your own screen name and file path: 
    This is a screenshot of the [screen/page name] screen in [app name]:
[paste the full file path to your screenshot here]

Please look at the real source code for this screen and identify every
visible control on it — buttons, icons, toggles, fields, anything a user
can tap or click. For each one, read the code to find out exactly what it
does. Don't guess — if you're not sure, say so instead of making it up.

Then give me back a plain JSON list, one entry per control, in exactly
this shape:

[
  { "label": "Back arrow", "text": "Exits and returns to your catalog", "x": 12.4, "y": 6.9 },
  { "label": "Pencil icon", "text": "Edit this Storyboard's label, cover image, and tags", "x": 87.2, "y": 6.9 }
]

"x" and "y" are your best estimate of where each control sits in the
screenshot, as a percentage of its width and height (0 = left/top edge,
100 = right/bottom edge).

    Paste whatever it gives back into "Load AI-generated pins" below and click Load. Every pin appears already placed. First time through, read what it produces closely — after two or three screens this becomes automatic.

  4. If any pin is crowding another one, or isn't quite on its control, long-press it and drag it to the right spot. Expect to do this — AI won't place every pin perfectly, and your own eyes will always be more accurate than its first guess. This step isn't a sign something went wrong.
  5. Click Copy Python snippet — this draws the numbered pins permanently onto the image itself.
  6. Click Copy help.html callout stub — this turns each pin into its coded object, and bundles all of them into the array that becomes part of the HTML artifact.
  7. Move to the next screen and repeat.

No AI agent handy, or want to place pins yourself instead? Skip step 3 and just click directly on the picture — each click drops the next pin, and you type its name and description yourself.

Updating an existing help article (a screen changed)
  1. Open help.html, find the article for that screen, and copy everything inside its callouts: [ ... ] list.
  2. Take a brand new screenshot of the screen as it looks today. Never reuse the old -annotated.png file — see "Where do screenshot files come from?" below for why.
  3. Use the same prompt template from "Documenting a screen for the first time" above, with one addition: paste in the old callouts text too, and add a line asking it to reuse each description for anything that still works the same way, and only write a new one for anything that actually changed.
  4. Load the new screenshot here, then paste what the AI gives you into "Load AI-generated pins" and click Load.
  5. Drag any pin that needs fine-tuning — expect to do this; your own eyes will always place a pin more accurately than the AI's first guess.
  6. Copy the Python snippet and the help.html stub, same as above.

Prefer to place pins yourself instead of trusting the AI's guessed positions? Use "Updating an existing screen" below — it queues up just the old names and descriptions, and you click the new screenshot once per pin to place it yourself.

Pasting the AI's answer failed — now what?

"Load AI-generated pins" only understands one thing: a plain list, in square brackets, like [{...}, {...}]. Some AI agents hand that back exactly as asked. Others wrap it in a sentence first ("Here's the list you asked for:") or fence it off in a code block (three backticks, then json, then the list, then three more backticks) — and if you paste that in as-is, you'll get an error instead of your pins.

The fix: before pasting, delete everything except the list itself — it should start with [ and end with ], nothing before or after. If your AI agent used a code fence, delete the ```` ```json ```` line at the top and the ```` ``` ```` line at the bottom too.

What's a "callout," and where do these live?

A callout is one row of a help article — a number, a short name, and a sentence saying what that thing does. Example: ① Back arrow — Exits and returns to your catalog. That's it — that's a callout.

All of them live in one file: onda-help/help.html. Inside it is one long list called ARTICLES. Each help topic (like "Storyboard — Overview") is one block in that list, and inside that block is a smaller list called callouts — that's the exact part you'd copy out.

To find the one you want: open help.html in a text editor, search for the screen's name (e.g. "Storyboard"), and copy everything between the square brackets after callouts:. That's what goes in the Import box below.

Where do screenshot files come from?

A screenshot here is just a regular picture file — the same kind you get from a screenshot key combo, or Snagit, or any screen-capture tool on your Mac. Nothing special about it.

"Choose a file" just opens the normal file-picker window — the same one you'd see attaching a photo to an email. You browse to wherever you saved the screenshot and click it. This tool doesn't care where that is.

One thing worth doing anyway: since the finished, annotated image eventually needs to live in onda-help/help-images/ for the real help website to use it, it saves a step to save your screenshot straight into that folder in the first place, rather than somewhere temporary you'd have to move it from later.

Important if you're updating a screen that already has help content: that folder will already have an old, annotated version of this screen sitting in it — a filename ending in -annotated.png, with the old numbered circles already drawn on it. Don't load that one. It's a picture of the old layout, and feeding it back into this tool would draw a second set of numbers right on top of the first. Take a brand new screenshot of the screen as it looks today, and load that instead — the old file is only useful for one thing: copying its callouts text out of help.html to paste into the Import box below, so the old descriptions carry over.

What do the three buttons at the bottom do?
  • Copy Python snippet — Copies the exact spots you clicked, so a computer program can draw the numbered circles for you.
  • Copy help.html callout stub — Makes a list with the name of each pin already filled in. Each one also has a spot called text — that's the explanation of what the button actually does. If you imported an old description for that pin, it carries over automatically. If a pin says "needs description" in the table, this tool doesn't know that part yet — you fill it in yourself after checking the real code.
  • Clear all pins — Erases every pin so you can start over.
